# Typola 桌面控件系统整体优化 Spec

- **状态**：已实现并通过验收
- **日期**：2026-07-26
- **代码基线**：`main` / Typola 2.0.7
- **目标版本**：后续常规版本，不在本任务内修改版本号
- **设计依据**：Typola 产品原则、Impeccable 完整控件审查、Codex App / Claude Desktop 等成熟桌面端的克制交互范式

---

## 1. Problem Statement

Typola 已经具备完整的文档编辑、文件操作、预览、终端、AI 工作台、设置和自定义颜色能力，但控件是随功能迭代逐步叠加的，尚未形成统一的桌面控件系统。当前主要问题不是“功能不够”，而是：

1. 顶部工具栏的一级功能过多，主次不明确；在 1024px 宽度下会溢出或裁切，右侧栏按钮不可稳定触达。
2. 文件、格式、视图、模式、设置等不同语义混在同一视觉层级，用户需要逐个识别图标。
3. 按钮、标签页、输入框、开关、弹层、对话框、面板标题栏的尺寸、圆角、字体、阴影和动效节奏不统一。
4. 设置页与 AI 配置区存在卡片套卡片、阴影偏重、圆角偏大、信息密度失衡的问题。
5. 菜单、对话框、Tooltip、图标按钮的键盘语义和可见焦点不完整，未稳定达到 WCAG 2.1 AA。
6. 右侧栏缺少与左侧栏同源的收起按钮；已有局部实现尚未进入版本，并且需要保证收起只改变布局样式，不卸载内容、不修改数据。
7. Define Color、选区浮条、快速打开、终端等局部控件各自成立，但组合后风格割裂。
8. 动效时长、缓动和关闭语义不一致，部分状态瞬切，部分状态又偏慢，缺少统一的 Reduced Motion 回退。

本次优化的真实目标不是模仿某个产品的皮肤，而是建立一套适合 Typola 的桌面控件语法：**像 Codex App、Claude Desktop 一样安静、清楚、可预测，同时保留 Typola“沉静 · 编辑 · 在场”的品牌气质和全部现有能力。**

---

## 2. Success Definition

完成后应满足：

1. 1024px、1280px、1440px 三个桌面宽度下，顶部工具栏无水平滚动、无裁切、无功能丢失。
2. 新建、打开、打开文件夹、保存、另存、插入表格、插入图片、导出入口始终直接可见；不把文件类操作折叠进“更多”菜单。
3. 低频格式和多种预览能力可以收进语义清晰的菜单，但所有原功能仍可在一级或二级一步触达。
4. 右侧栏切换按钮与左侧按钮为同一图标的镜像；收起后内容保持挂载、状态和数据不变，再展开可原样恢复。
5. 全局控件遵循同一尺寸、间距、圆角、字体、边框、阴影、图标和动效尺度。
6. 设置、AI、颜色、选区浮条、快速打开、终端、菜单和对话框的视觉层级一致。
7. 所有可交互控件具备 hover、active、focus-visible、disabled、loading 或 selected 等适用状态。
8. 菜单支持方向键、Home/End、Enter/Space、Escape；对话框支持焦点进入、Escape 和明确关闭。
9. Windows 显示 `Ctrl` 快捷键，macOS 显示 `⌘`；Tooltip 同时表达动作和平台快捷键。
10. `prefers-reduced-motion` 下移除位移动画和长过渡，功能与状态反馈仍完整。
11. 相关目标测试、类型检查、构建和视觉验收全部通过。

---

## 3. Product and Design Invariants

以下是不允许被本次视觉优化破坏的约束：

1. **写作者第一，AI 第二**：正文始终是视觉主角，AI 控件不能成为主界面最重元素。
2. **不更换品牌色板**：继续使用现有暖米黄、暖橙和主题 token；本次只统一使用方式。
3. **编辑内容保留衬线，界面控件使用无衬线**：正文、品牌标题保留编辑感；按钮、菜单、设置、状态文字以高可读性为先。
4. **文件操作不折叠**：用户已明确要求，顶部文件操作保持直接可见。
5. **Define Color 按钮保留**：它是产品差异化入口，不降级为设置页隐藏项。
6. **右栏收起不碰数据**：只改变宽度、透明度、交互可达性和布局类名，不关闭当前模式、不清空内容、不重置宽度、不触发保存。
7. **不引入新的业务状态模型**：控件系统只统一表达和交互，不重构编辑、预览、导出、终端或 AI 数据流。
8. **不增加新 UI 依赖**：继续使用现有 React、Floating UI、Motion、Lucide 和 CSS token。
9. **本地优先**：任何视觉与交互改进都不得依赖网络或账号。
10. **键盘可达是默认能力**：鼠标、触控板和键盘应得到等价结果。

---

## 4. Solution Overview

本次采用“基础契约 + 关键原语 + 分模块迁移”的方案：

1. 先建立统一的控件 token：尺寸、间距、圆角、字体、边框、阴影、层级、动效。
2. 提炼最少量共享原语：图标按钮、菜单、对话框外壳、面板标题栏、Tooltip。
3. 先重构顶部工具栏的信息层级和响应式行为，确保最窄桌面宽度稳定。
4. 再统一设置页、AI 配置、Define Color、选区浮条、快速打开和终端。
5. 最后补齐键盘语义、平台快捷键、焦点、Reduced Motion 和全状态视觉。

该方案不追求一次性组件化整个应用；只抽取至少有两个真实使用者、且能消除行为分叉的控件原语。

## 5. Information Hierarchy

### 5.1 顶部工具栏分区

从左到右分为六个语义区：

1. **工作区导航**：左栏、Define Color、文档大纲。
2. **文件与插入**：新建、打开、打开文件夹、保存、另存、表格、图片、导出。
3. **高频编辑**：加粗、斜体、链接；其余格式进入“更多格式”。
4. **视图与工具**：源码、预览/产物、终端。
5. **应用级控制**：设置、文档模式。
6. **右侧栏**：最右侧独立放置镜像侧栏按钮。

各区只通过 8px 间距和必要的弱分隔表达，不使用多个描边胶囊包裹每组按钮。

### 5.2 控件权重

| 权重 | 场景 | 表达 |
|---|---|---|
| Primary | 对话框确认、明确提交 | 实色或强调色，仅一个 |
| Secondary | 设置动作、重试、选择 | 轻边框或弱底色 |
| Tertiary | 工具栏、面板操作 | 默认透明图标按钮 |
| Destructive | 删除、放弃 | 危险色 + 文案/图标，不只靠颜色 |

### 5.3 桌面布局层级

1. 顶部工具栏负责全局与当前文档动作。
2. 左右侧栏负责上下文导航和辅助工作流。
3. 面板内部标题栏只负责本面板动作，不重复全局关闭按钮。
4. 浮层只承载短时选择；复杂配置进入设置或对话框。

## 6. Control Foundation

### 6.1 Typography

| 用途 | 字体 | 尺寸 | 字重 |
|---|---|---:|---:|
| 工具栏 / 菜单 / 设置控件 | 系统无衬线 UI 栈 | 13px | 400–500 |
| 辅助信息 | 系统无衬线 UI 栈 | 12px | 400 |
| 面板标题 | 系统无衬线 UI 栈 | 13px | 600 |
| 对话框标题 | 现有品牌/正文字体 | 18px | 600 |
| 正文与编辑内容 | 现有正文衬线栈 | 保持现状 | 保持现状 |

规则：

- 控件中不使用正文衬线字体。
- 仅在品牌标题、文档内容和需要编辑感的展示标题中保留衬线。
- 英文菜单不使用全大写；中文不额外增加字距。

### 6.2 Size Scale

| 控件 | 视觉尺寸 | 图标 |
|---|---:|---:|
| 顶部工具栏 | 44px 高 | — |
| 顶部图标按钮 | 32 × 32px | 16px |
| 面板标题栏 | 40px 高 | — |
| 面板图标按钮 | 28 × 28px | 14–15px |
| 输入框 / 下拉 / 常规按钮 | 32px 高 | 14–16px |
| 标签页 | 30–32px 高 | 14px |
| 紧凑菜单项 | 32px 高 | 14–16px |
| Switch 视觉轨道 | 28 × 16px 或 32 × 18px | — |
| Switch 最小点击区 | 32 × 32px | — |

所有图标按钮至少保留 32px 可点击区域；不能为了塞下更多功能而缩到难以点击。

### 6.3 Spacing Scale

合法间距只使用：

`2 / 4 / 6 / 8 / 12 / 16 / 24 / 32px`

推荐映射：

- 图标与文字：6px
- 同组控件：2–4px
- 控件组之间：8px
- 表单行内部：8–12px
- 设置分区之间：24px
- 对话框主体边距：24px

### 6.4 Radius, Border and Shadow

| 层级 | 圆角 |
|---|---:|
| 微型状态、色块 | 4px |
| 按钮、输入、菜单项 | 6px |
| 菜单、Popover、浮条 | 8px |
| 对话框 | 12px |

规则：

- 禁止无语义的 16–24px 大圆角卡片。
- 普通设置行和 AI Provider 行使用分隔线或弱底色，不使用浮空卡片阴影。
- 阴影只用于离开文档平面的浮层：菜单、Tooltip、Popover、对话框。
- 阴影采用轻量两层表达；暗色主题降低黑色面积，优先使用边框分层。

### 6.5 Color

- 只使用现有主题语义 token，不新增硬编码品牌颜色。
- Accent 只用于 focus、selected、进度和需要注意的状态。
- Hover 优先使用弱背景；active 同时使用背景和前景变化。
- 危险、成功、警告状态同时提供图标或文案。
- 所有文字和控件边界满足 WCAG 2.1 AA 对比度要求。

### 6.6 Motion

| 场景 | 时长 | 说明 |
|---|---:|---|
| 按压反馈 | 60ms | 仅轻微明暗/缩放 |
| Hover / Focus | 120ms | 颜色与边框 |
| 菜单 / Tooltip | 140ms | 透明度 + 2–4px 位移 |
| 对话框 | 160ms | 透明度 + 小幅缩放 |
| 面板 / 标签指示器 | 180ms | 宽度或 transform |

统一缓动：

- 进入：`cubic-bezier(0.22, 1, 0.36, 1)`
- 状态变化：`ease-out`
- 退出：较进入短 20–30ms

禁止：

- 大幅弹簧、回弹、旋转和装饰性 shimmer。
- 420ms 以上的常规控件动画。
- 同一动作同时动画宽度、缩放和大范围位移。

Reduced Motion：

- 位移与缩放归零。
- 面板可以瞬时切换宽度，保留颜色和可见状态反馈。
- 加载状态以静态图标/文本或极短透明度反馈替代连续动画。

### 6.7 Layer Scale

语义层级固定为：

1. Base content
2. Sticky chrome
3. Dropdown / Popover
4. Modal
5. Toast
6. Tooltip

业务组件不得自行使用任意超大层级值。

### 6.8 Iconography

- 全部使用 Lucide 线性图标。
- 顶部统一 16px、`strokeWidth` 1.6。
- 面板统一 14–15px、`strokeWidth` 1.6。
- 同一语义只保留一个图标映射。
- 右侧栏按钮直接复用左侧 `PanelLeft` 的水平镜像，不使用风格不同的 `PanelRight`。
- 图标按钮必须有可访问名称，不能靠图形猜测。

## 7. Shared Interaction Contracts

### 7.1 Icon Button

必须支持：

- 默认、hover、active/pressed、focus-visible、disabled、loading。
- `aria-label`；切换按钮使用 `aria-pressed`。
- 点击后 Tooltip 立即关闭。
- 禁用态保留语义但不接受操作。

### 7.2 Menu

必须支持：

- 触发器表达 `aria-haspopup` 和 `aria-expanded`。
- 打开后焦点进入当前选中项或第一项。
- `ArrowDown` / `ArrowUp` 循环导航。
- `Home` / `End` 跳到首尾。
- `Enter` / `Space` 执行。
- `Escape` 关闭并把焦点还给触发器。
- 点击外部关闭。
- 菜单项支持 active、disabled 和必要的快捷键列。

### 7.3 Tooltip

- 350ms 后显示，离开或点击立即关闭。
- 同时支持 hover 和键盘 focus。
- 结构为“动作名称 + 平台快捷键”，快捷键弱化显示。
- 不为已带清晰文字的普通按钮重复显示 Tooltip。

### 7.4 Dialog

- 使用正确的 `dialog` 语义、模态属性和标题关联。
- 打开后焦点进入第一个合理控件。
- `Escape` 关闭；危险确认场景除外时必须提供明确说明。
- 右上角有统一关闭按钮。
- Footer 中只有一个 Primary 动作。
- 关闭后焦点回到打开入口。

### 7.5 Panel Header

- 高度统一为 40px。
- 左侧标题，右侧最多 2–3 个图标动作。
- 面板外壳拥有关闭/收起语义，内容组件不重复渲染第二个关闭按钮。
- 溢出动作进入“更多”菜单。

## 8. Module Specifications

### 8.1 Top Toolbar

#### 宽屏（≥ 1360px）

- 文件与插入动作全部直接显示。
- 高频格式显示加粗、斜体、链接；引用、列表、任务列表、格式刷进入“更多格式”。
- Word、公众号、AI 产物进入“预览与产物”菜单。
- 文档模式显示图标和完整文字。

#### 中屏（1180–1359px）

- 文件与插入动作仍全部直接显示。
- 高频格式维持三个按钮 + “更多格式”。
- 预览保持单一菜单。
- 文档模式使用更紧凑的文字宽度。

#### 窄桌面（1024–1179px）

- 文件与插入动作仍全部直接显示。
- 所有格式能力聚合为一个“格式”菜单；快捷键继续工作。
- 预览保持单一菜单。
- 文档模式保留三个图标段，文字通过 Tooltip 表达。
- 设置和右侧栏按钮始终可见。
- 不允许工具栏横向滚动。

#### 更窄窗口（< 1024px）

- 继续保证文件动作、设置和左右侧栏可触达。
- 格式、预览、模式采用最紧凑表达。
- 允许中心拖拽区域缩小，但不允许任何按钮被裁掉。

其他规则：

- 工具栏按钮从 34px 统一为 32px，图标从 18px 统一为 16px。
- 工具栏保持 44px 高。
- 文件操作入口顺序稳定，不因窗口宽度重新排序。
- 所有菜单使用共享菜单交互，不各自维护键盘逻辑。

### 8.2 Right Sidebar

- 最右侧按钮与左侧栏按钮为镜像关系。
- 仅当已有右侧内容模式时可收起；没有内容时为 disabled。
- 收起时：
  - 保留当前右侧模式和挂载树。
  - 保留滚动位置、输入状态、预览状态、运行状态和用户调整宽度。
  - 隐藏 resizer。
  - 侧栏不可聚焦、不可点击、对辅助技术隐藏。
  - 主编辑区恢复可用宽度。
- 展开时恢复收起前宽度和全部状态。
- 切换到另一个右侧模式时，默认沿用当前收起状态；用户主动打开新预览时可自动展开，但不得清空旧模式数据。
- 使用 180ms 宽度过渡；Reduced Motion 下立即完成。

### 8.3 Settings

导航重新分组：

1. **写作**：通用、编辑器、图像
2. **呈现**：预览、外观、Word、HTML
3. **工具**：终端、AI
4. **关于**：固定在底部

规则：

- 设置窗具备标题、明确关闭按钮和对话框语义。
- 导航行高度一致，不使用大胶囊。
- 表单行统一标签、描述和控件对齐。
- Toggle 使用同一组件和点击区。
- 设置分区使用留白和分隔线，不使用层层卡片。
- 主题预览保留视觉样例，但降低阴影和圆角。

### 8.4 AI Settings and Composer

- Provider 从“阴影卡片墙”改为扁平可展开列表。
- 每行展示名称、状态、关键摘要和展开箭头；展开后再显示路径、模型和诊断项。
- 删除大面积粉色/强调色嵌套背景；强调色只标记选中、成功连接或警告。
- Composer Footer 分为上下文/附件组与发送组。
- 发送按钮固定为 32 × 32px 图标按钮。
- Provider 和模型在窄面板下合并到一个紧凑选择入口。
- 小于 360px 宽时不得出现控件重叠或多行按钮挤压。
- 运行、失败、取消和重试都有可理解文字，不只显示内部错误。

### 8.5 Define Color

- 顶部按钮永久保留。
- Popover 圆角从夸张大圆角收敛到 8px，阴影与其他 Popover 同源。
- 首屏展示 8 个最近使用或精选预设。
- “全部颜色”展开完整 50 色网格，不删除任何预设。
- 英文内部命名本地化为用户可理解的中文标签。
- 滑杆支持方向键和可见焦点，并提供当前值。
- 色块选中态同时使用边框/勾选，不只依赖颜色。

### 8.6 Selection Floating Bar

- 一级只保留四个最高频选区动作。
- 文档级、全局级或低频能力进入“更多”菜单。
- 浮条使用 8px 圆角和轻阴影。
- 出现/消失为 140ms 透明度 + 2px 位移。
- 键盘可进入、Escape 可关闭。

### 8.7 Quick Open

- 未保存文档显示“未命名文档”，不暴露内部 `untitled-*` 标识。
- 列表项清晰区分文件名与路径。
- 当前选中项同时有背景和文本权重变化。
- 支持方向键、Enter 和 Escape。

### 8.8 Terminal

- 标题栏按钮统一尺寸和 Tooltip。
- 新建、关闭、重试、清空等动作必须有可访问名称。
- 启动失败显示用户可理解原因，并提供“重试”和“查看诊断”。
- 内部异常标识不直接作为主文案展示。
- 标签页选中态与其他面板标签页一致。

### 8.9 Menus, Popovers and Context Controls

- 导出、“更多格式”、“预览与产物”等共用同一菜单实现。
- 菜单宽度由内容决定，限制在窗口安全区内。
- 编辑器右键菜单、图片 Popover、预设 Popover 共享圆角、边框、阴影和菜单项高度。
- 避免 Popover 内再嵌套视觉卡片。

## 9. User Stories

### 9.1 工具栏

1. **作为写作者**，我能在任何支持的窗口宽度直接新建、打开、打开文件夹、保存和另存文档，不需要先打开“更多”菜单。
2. **作为写作者**，我能直接插入表格和图片，并从固定导出入口选择 PDF 或 Word。
3. **作为写作者**，我在宽屏下能快速使用加粗、斜体和链接，在窄屏下仍能从格式菜单找到全部格式能力。
4. **作为写作者**，我能从一个清楚命名的入口打开 Word、公众号或 AI 产物预览。
5. **作为键盘用户**，我能完整操作工具栏菜单并把焦点返回触发按钮。
6. **作为窄窗口用户**，我在 1024px 下仍能看到设置和右侧栏按钮，界面不出现横向滚动。

### 9.2 侧栏与面板

7. **作为写作者**，我能通过左右镜像的图标理解两侧栏的对应关系。
8. **作为写作者**，我收起右栏后正文获得更多空间，再展开时预览和 AI 状态保持原样。
9. **作为正在运行 AI 任务的用户**，我收起右栏不会终止任务、清空输出或改变任何数据。
10. **作为使用屏幕阅读器的用户**，我不会在收起的右栏中意外导航到不可见控件。

### 9.3 设置与 AI

11. **作为新用户**，我能按“写作 / 呈现 / 工具”理解设置结构。
12. **作为设置用户**，我始终能看到明确关闭按钮，并可使用 Escape 返回编辑器。
13. **作为 AI 用户**，我能快速看出当前 Provider 是否可用，而不被多层卡片和装饰干扰。
14. **作为 AI 用户**，我只在需要时展开 Provider 的路径、模型和诊断详情。
15. **作为窄面板用户**，我能正常输入和发送，不会因 Provider、模型和附件控件挤占输入空间。

### 9.4 颜色与局部工具

16. **作为 Define Color 用户**，我仍能从工具栏直接打开颜色系统。
17. **作为 Define Color 用户**，我能先访问常用预设，也能展开看到全部 50 个预设。
18. **作为键盘用户**，我能操作颜色滑杆并知道当前值和选中状态。
19. **作为选区工具用户**，我只看到最常用动作，低频能力仍能从更多菜单找到。
20. **作为快速打开用户**，我不会看到内部临时文件 ID。

### 9.5 可访问性与动效

21. **作为键盘用户**，我在所有按钮、菜单、标签和表单控件上都能看到清晰焦点。
22. **作为 Windows 用户**，我看到 `Ctrl` 形式的快捷键；作为 macOS 用户，我看到 `⌘` 形式。
23. **作为 Reduced Motion 用户**，我不会看到位移、缩放或长过渡，但状态仍清楚。
24. **作为暗色主题用户**，我看到的边框、文字和焦点不会因硬编码亮色而失去对比。
25. **作为长时间写作者**，我感受到控件安静、一致，不需要反复辨认相同语义的不同样式。

## 10. Implementation Decisions

1. 使用现有主题 token 作为颜色基础，补充控制尺寸、间距、圆角、层级和动效语义别名。
2. 共享原语只覆盖明确重复的行为：Icon Button、Menu、Dialog Shell、Panel Header、Tooltip。
3. 菜单基于现有 Floating UI，实现单一键盘与焦点管理逻辑。
4. 面板与模式过渡继续使用现有 Motion 能力，但统一时长并接入 Reduced Motion。
5. 响应式主要使用 CSS 容器/媒体规则，不读取窗口宽度写入业务状态。
6. 文件操作永远在 DOM 和视觉中保持直接可见；响应式只压缩格式、预览和模式表达。
7. 右栏 collapsed 是纯 UI 状态，与 right panel mode 和业务内容状态分离。
8. 右栏保持挂载，通过宽度、可见性、`inert` 和辅助技术属性控制交互。
9. 平台快捷键通过单一格式化函数生成，不在各组件硬编码 `Ctrl` 或 `⌘`。
10. 保持已有业务回调和数据接口，优先以展示组件和 CSS 迁移完成目标。
11. 不做大规模 CSS 重写；只在控件相关区域建立可追踪的语义层，并清理本次迁移造成的旧规则。
12. 用户可见变化同步写入 Changelog；控件分层与右栏状态契约同步写入架构文档。

## 13. Acceptance Scenarios

1. 在 1024px 宽窗口依次点击新建、打开、打开文件夹、保存、另存、表格、图片和导出，入口均直接可见且功能触发正确。
2. 在 1024px 宽窗口打开格式菜单，能执行加粗、斜体、链接、引用、三类列表和格式刷。
3. 仅用键盘打开格式菜单，使用上下方向键移动、Enter 执行、Escape 关闭，焦点返回触发器。
4. 打开 Word 预览，滚动并调整宽度；收起右栏，再展开，模式、滚动和宽度保持。
5. AI 任务运行时收起右栏，任务继续；展开后输出仍在。
6. 右栏收起时 Tab 不会进入不可见内容。
7. 设置页导航按三组显示，右上角关闭与 Escape 都可返回原焦点。
8. AI Provider 默认是扁平摘要，展开后显示完整配置；360px 面板宽度下 Composer 不重叠。
9. Define Color 首屏有 8 个精选/最近色，展开后仍可访问全部 50 个预设。
10. Quick Open 对未保存文档显示“未命名文档”，不显示内部 ID。
11. 暗色主题下按钮焦点、菜单边框、次级文字达到可读对比。
12. Reduced Motion 下菜单、对话框和面板没有可感知位移或缩放动画。
13. 全量测试、类型检查和生产构建通过。

## 14. Out of Scope

1. 不修改编辑器数据模型、Markdown 语法或保存链路。
2. 不修改 Word / PDF / HTML / 公众号导出的内容与排版算法。
3. 不新增或删除 AI Provider、Agent 能力或模型配置字段。
4. 不修改工作区、多标签或终端后端行为。
5. 不更换主题色板、不重做编辑器正文排版。
6. 不增加移动端专用布局；本次只保证桌面窄窗口。
7. 不做版本发布、版本号提升或安装包发布。
8. 不合入当前原工作区中的教程、研究记录、任务记录等无关改动。
9. 不恢复已废弃的 Electron、Milkdown、全局搜索或行业专项能力。

## 15. Risks and Mitigations

| 风险 | 缓解 |
|---|---|
| 工具栏响应式隐藏导致功能误丢失 | 文件动作永不隐藏；每个折叠组做组件测试和 1024px 视觉测试 |
| 右栏宽度动画触发内容卸载 | collapsed 与 mode 分离，测试挂载身份和状态保持 |
| 共享菜单改动影响导出 | 保留原回调契约，补导出和键盘回归 |
| CSS 大文件特异性冲突 | 使用控件语义类和有限 token，清理被替代规则，避免全局通配覆盖 |
| Define Color 主题覆盖失真 | 单独验证默认主题、暗色和 Define Color 三条路径 |
| 设置/AI 结构调整影响测试选择器 | 优先按 role/label 测试，避免依赖纯样式类 |
| 动效统一造成性能问题 | 只动画 transform/opacity；面板宽度限制在单个 shell，resizing 时禁用过渡 |

## 16. Further Notes

- “类似 Codex App / Claude Desktop”在本 Spec 中指：克制的控件密度、清晰层级、稳定桌面语义、统一图标和优雅状态过渡；不复制其品牌色、布局皮肤或 AI 对话中心化定位。
- 本次 Impeccable 审查中的 P1 全部纳入实现，P2 中与控件系统直接相关的项一并纳入。
- 若实现过程中发现需要改变文件操作常驻、右栏纯样式收起或现有业务数据流，必须暂停并重新与用户对齐；其余局部视觉取舍以本 Spec 为准执行。
