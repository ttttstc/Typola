## 诊断结论(四个只读子代理,2026-09-26)

### 重大澄清
**Vditor 已不是编辑内核**。所见即所得 = CM6 + @atomic-editor live preview(Cm6MarkdownEditorPane);Vditor 仅在 PreviewPane.tsx:77-82 渲染 AI 会话消息(不在按键热路径)。

### 1. 冷启动路径(当前 ~2.6s,claude.ai 同类指标优化前 3.1s→优化后 0.55s)

**首屏 eager JS 约 2.1MB raw / 623KB gzip**(9 JS + 1 CSS),加 1.32MB 思源宋体(font-display:swap 不阻塞):

| 文件 | raw/gzip KB | 问题 |
|---|---|---|
| index-*.js | 676/~157 | AppLayout.tsx:33-53 静态引入全部 AI/检视/产物面板 |
| docx-vendor | 353/99 | **白拉**——settingsService.ts:13 仅为 `DEFAULT_PRESET_ID` 常量把整个 docx vendor 拖进首屏 |
| TerminalPanel | 353/88 | AppLayout.tsx:2900-2931 无条件渲染,visible 只挡 PTY 不挡 chunk 加载 |
| editor-language-vendor | 296/107 | markdownAnalysisService.ts:1 静态拉 @lezer/markdown,但分析是 180ms 防抖,首帧不需要 |
| word-*.js | 48/14 | 同 docx 链 |
| editor-core-vendor | 239/78 | 必需 |
| react-vendor | 185/60 | 必需 |

**启动事件序列问题**:
- 恢复上次文件:systemOpenChecked(等 Tauri IPC)→ **固定 700ms setTimeout**(AppLayout.tsx:2193)→ requestIdleCallback(1500ms timeout)→ 读盘→注入。**编辑器能用之前叠了 ≥700ms 人为延迟**
- SettingsPage 预热在启动关键期抢带宽(AppLayout.tsx:727)
- 上次文件内容注入走 read_opened_document → JSON number[] IPC(每字节 3-4 字符膨胀)

**Rust 侧启动**:
- main() 前串行 3 次 `reg query` 子进程探测 WebView2(每次 60-200ms,lib.rs:100-131)
- Cargo.toml **无 [profile.release]**:无 lto/strip/codegen-units=1

### 2. 编辑输入热路径(打字 p95 帧间隔 53ms,预算 16.7ms)

一次按键链路(见 EditorPane.tsx:124-133 → useFileTabs.ts:802-832 → AppLayout 重渲染):
- **每键 ≥3 次全文 `doc.toString()`**:headingFold(ts:52)、previewSync(ts:86)、mathPreview(ts:117)各物化一次 100KB 字符串
- **analyzeMarkdown 缓存 hash 是逐字符 O(n)**,miss 时全文 lezer 重解析;previewSync 侧再 hash 一次
- **calculateStats 多趟全文正则**,CJK `\p{Script}` match 极贵(中文长文数十 ms)
- atomic-editor inlinePreview 每键全语法树 walk + ensureSyntaxTree(200ms 预算)
- 微信预览面板开着时**无 debounce** 仅 useDeferredValue → 每键全文 unified 流水线(全主线程,无 worker)
- Word 预览面板 260ms debounce 后整篇 unified + 双 rAF 分页

自动保存链(800ms debounce 后):
- Rust: atomic_write(sync_all fsync ×2)→ document_fingerprint **整文件读回+逐字节 hash**
- watcher 指纹校验再整读一次(未命中自写计数时)

### 3. React 渲染(每键 3 次 setState → 全树重渲染)

- **AppLayout 巨型单组件(3128 行,~50 useState),全仓 0 处 React.memo**
- 每键 handleContentChange → setFile+setOpenTabs+setSaveVisualState,工具栏/文件树/状态栏全量重渲染
- **FileTreePanel 递归 TreeNode 无 memo 无虚拟化**,1000+ 文件展开时每键 1000+ 次 render
- agentChangedPaths: new Set(...) 内联构造(AppLayout.tsx:2845),FileTreePanel 永远判定 props 变化
- 主题系统优秀(构建期 CSS 变量,不触发 React);PaperTexture WebGL 默认关闭;auto-animate 非常驻

### 4. Rust/Tauri(整体健康,少量硬伤)

- 同步命令阻塞主线程:agent_detect(最长 5s wait_timeout)、scan_artifacts(递归扫盘)、read_opened_document、list_directory_entries 均非 async
- 文件内容 IPC 走 JSON number[](3-4 倍膨胀),未用 tauri::ipc::Response 原始字节
- 文档 watcher 无防抖,每个 modify 事件立即 emit;workspace watcher 跨事件无合并(git checkout/AI 批量写盘=IPC 风暴)
- agent-stdout 逐行 emit;terminal_data 每 8KB emit
- scan_artifacts 对同一棵树扫两遍 + collect_archived_manifests O(n²)

### 5. 现有棘轮的漏洞

- perf/_lib.mjs:10-13 hash 剥离正则 `[0-9a-f]{8,16}` **匹配不了 rolldown base64 hash**(如 `DCak0R5o` 含大写)→ 每次构建都是新 key → 状态 "untracked" 而非 "regressed" → **任何 chunk 都逃过预算棘轮**
- dist 不清理,旧 hash 文件滞留(perf-budget.json 里 index-C89eHEJK/DfRZxh2W 双份 156.9KB 为证)
- 棘轮只测 gzip 体积,不覆盖 eager/lazy 分类、modulepreload 集合、启动运行时指标
