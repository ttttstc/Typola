### 诚实结论:哪些赢了,哪些没赢

**赢了的(可测量)**:
- 冷启动 -10%(≈160ms/次),来源:700ms 死延迟移除+docx 112KB 首屏剥离+TerminalPanel 按需+lto
- 首屏 eager JS:622.51 → 511.06KB gzip(**-111KB / -18%**)
- exe 体积:25.0MB → 23.2MB(lto thin 生效但未到预期 ~15MB,icons 资源占大头)
- 每键分析成本:3 次全文物化+2 次 O(n) hash → 1 次(共享 WeakMap 缓存)
- CJK 统计:1.3ms → 0.3ms/次(4x)
- AI 流式输出 IPC:逐行 → 16ms/64 行批(风暴时 10-100x)
- 保存链路:少 1 次全文件读回;watcher 事件 120ms 合并
- **UI 不再被 agent_detect 冻住**(原来设置页探测 CLI 时整个 UI 卡最多 5s)
- 棘轮从失效修到完备(这是本轮最重要交付:所有战果从此只许降不许升)

**没赢的(如实说)**:
- C 打字 p95 帧间隔仍 ~53-67ms,31 个长任务未减。分析:2.1-2.4 消除的是每键固定开销(约 3-5ms/键),但长任务主体是 **atomic-editor inlinePreview 的语法树 walk + ensureSyntaxTree(200ms 预算)**——它在依赖包里,且 CDP 注入打字比真实键盘路径更重。要真正压下 p95 需动 @atomic-editor 的 inlinePreview 增量化(上游依赖,牵扯大),本轮没做
- 1.7(IPC 原始字节)、1.9(静态骨架)、3.3(AppLayout 拆分)按 ROI 放弃/顺延(见实验日志)

## 风险

- watcher 防抖 120ms:外部工具改文件的提示最多晚 120ms 出现(自写文件走 pendingSelfWrites 计数不受影响)
- agent-stdout 批量:16ms 窗口内多行合并,前端逐行回放语义不变;极端情况(单行>16ms 间隔)行为与原来一致
- reg.exe→API 回退:注册表 API 失败自动回退 reg.exe,检测不会漏
- dirtyPaths 序列化 key:路径含空格时 join(' ') 仍无歧义(split(' ') 后每段都是完整路径)
